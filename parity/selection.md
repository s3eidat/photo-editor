## Hooks this lane added to shared files
All marked `// lane:selection` (or `<!-- lane:selection -->`).
- `index.html`: script tags for `js/select/*` and `js/layers/*`, after `ui.js`, before `app.js`.
- `js/ui.js`: `ED.ui.MENUS`, `ED.ui.TOOLS`, `ED.ui.w` (option/dialog widgets) exposed so lanes can add menu items, tools and dialogs.
- `js/core.js`: `PE.drawHook` (lane compositor, returns false to keep the original loop), `PE.snapExt` / `PE.restoreExt` (extra layer fields in undo snapshots), `PE.kindsExt`, `PE.parseExt`, `PE.saveExt`, `PE.openExt` (extra layer kinds/fields in .s3photo files; layers also keep their id as `uid`).
- `js/core.js`: `PE.surfaceExt[kind]`, `PE.vboxExt[kind]` (pixels / box of new layer kinds).
- `js/editor.js`: `PE.editableExt` (extra editing rules), `PE.shiftExt` (move members / linked layers), `PE.xfExt[kind]` (transform of new kinds).
- `js/editor.js`: lock-transparency lines in `applyStroke`, `fillWith` and `applyGradient` (`L.lockA` → `source-atop`).
- `js/editor.js`: `PE.xfAny(L, m, xf)` runs for every layer in transformLayer (vector masks).
- `js/ui.js`: `ED.ui.propsTail(P, L)` at the end of Properties for built-in layer kinds.
- `js/ui.js`: `ED.ui.layersExt` (Layers panel as a tree), `ED.ui.propsKind` (Properties for new kinds), `PE.dupExt`, `PE.removeExt`, `PE.mergeExt`, `PE.moveExt` (layer operations that understand groups).
- `js/ui.js`: `ED.ui.optsTail` — array of `f(tool, items)` that append controls to the tool options bar.
- `index.html`: CSP `script-src 'self' 'wasm-unsafe-eval'`; vendored `lib/ort.*` (ONNX Runtime Web, MIT) and `models/u2netp/` (Apache-2.0), see `models/LICENSES.md`.
- `js/editor.js`: `PE.offsetExt(L, dx, dy)` in crop/canvas size and `PE.scaleExt(L, kx, ky)` in image size, for layer kinds with their own geometry.
- `js/editor.js`: `ED.emit("overlay", {c, docPath, dpr})` at the end of the overlay paint, so lanes can draw previews.
- `js/editor.js`: tools in `ED.TOOLS` flagged `brush: true` get the round brush cursor.
- `js/ui.js`: `ED.ui.keys` — array of key handlers `f(e) -> true if handled`, run before the built-in shortcuts.
- Self-test: `PE.sx.tests` (array of `async (ok, near) => {}`) runs after the app's own `S3_SELFTEST`; no change to `app.js`.

## Integration notes (for merging the five lane branches into main)
Tried on 29 Oct by merging every lane branch onto this one in a scratch worktree:
- Conflicts are only neighbouring hook lines in `index.html`, `js/ui.js`, `js/editor.js`, `js/core.js`: keep both sides.
  Script order that works: this lane's block right after `js/ui.js`, then paint, vector, files/workspace; the adjust lane loads after `app.js`.
- With all five lanes merged (re-checked 29 Oct, latest heads), `S3_SELFTEST()` returns true and this lane's end-to-end scripts run without console errors.
- This lane renamed its Properties hook to `ED.ui.propsKind` because the vector lane uses `ED.ui.propsExt` as a list.
- Adjustment layers accept any colour op in `ED.ADJ`: filters registered in the adjust lane's Filter menu (`PE.adjUI.FILTERS`), `proxy` specs and
  anything that fails a pixel-shuffle test are left out; specs with their own `ui(el, st)` get a "More settings…" dialog (live, Cancel restores).
- Locked transparency is enforced in `PE.editPixels` / `PE.tileEntry`, so the paint lane's engine respects it on commit (its live preview does not).
- The files lane's PSD code reads `PE.sx.tree`, `L.parent`, `L.clip`, `L.fillOp` and group `open`: those names are stable.
- Optional layer fields `L.maskDensity` (0..1) and `L.maskFeather` (px) soften a mask without changing its pixels; `PE.sx.effMask(L, L.mask)` returns the mask the compositor uses (PSD export can write them as the mask's density / feather parameters, or bake that canvas).
